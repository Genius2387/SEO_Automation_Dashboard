## 1. Executive Summary

Phase 6 implements the **Claude AI Analysis Engine** for the Edgelink Technology SEO Automation Dashboard. It consumes validated, structured `NormalizedAuditData` generated by the Phase 4 Fetch + Cheerio crawler, binds and isolates untrusted webpage content to protect token budgets and prevent prompt injection, and executes evidence-grounded technical analysis adhering strictly to the assessment output contract.

Deterministic scoring safeguards enforce integer boundaries $[0, 100]$ and mathematical consistency across 5 core technical categories using documented weights. The BullMQ worker lifecycle has been extended with the `CRAWLING` ──► `ANALYZING` ──► `COMPLETED` pipeline, featuring intelligent crawl data reuse on retries, strict credential protection, and unrecoverable error policies.

## 4. Prompt Design, Versioning & Defenses

- **Prompt Version:** `PROMPT_VERSION = "2026.1"` (included in `audit_version` output field).
- **Evidence-Grounded Persona:**
  - Evaluates only supplied crawl headers, on-page signals, schema blocks, and verified provider data.
  - Strictly prohibits fabricating traffic, competitor statistics, backlinks, or Google penalties.
- **Absence vs. Failure Rule:**
  - If external provider metrics are unavailable or unconfigured, Claude explicitly notes data absence and never penalizes the overall score.
- **Prompt Injection Isolation:**
  - All scraped web page text and metadata are wrapped inside isolated XML tags (`<crawl_evidence>...</crawl_evidence>`).
  - System instructions explicitly mandate that external webpage strings are untrusted data and must never be treated as executable instructions.
- **Token Budget Bounding:**
  - `prepareBoundedCrawlData()` truncates raw DOM strings (title $\le 120$ characters, description $\le 200$ characters, findings $\le 20$, headings bounded) to guarantee predictable token expenditure.

## 6. Scoring Formula & Deterministic Safeguards

To prevent LLM mathematical hallucination, `enforceDeterministicScoring()` applies an exact weighted formula:

$$\text{overall\_score} = \text{round}\Big(0.25 \cdot \text{technical} + 0.25 \cdot \text{on\_page} + 0.20 \cdot \text{content} + 0.15 \cdot \text{core\_web\_vitals} + 0.15 \cdot \text{schema}\Big)$$

### Category Interpretations:
1. **Technical (25%):** HTTP status, canonical tags, indexability directives, robots.txt, and XML sitemaps.
2. **On-Page (25%):** Title tag optimization, meta descriptions, H1-H3 hierarchy, image alt text, and link integrity.
3. **Content (20%):** Visible word count, content depth, readability, and thin content prevention.
4. **Core Web Vitals (15%):** Largest Contentful Paint (LCP), Cumulative Layout Shift (CLS), and render-blocking resources.
5. **Schema (15%):** Schema.org structured data, JSON-LD validity, and Microdata discovery.

## 7. BullMQ Worker Integration & Lifecycle

The worker (`src/workers/auditWorker.ts`) handles end-to-end job execution:

1. **Record Verification:** Loads audit record from PostgreSQL; skips if already `COMPLETED`.
2. **Crawl Optimization:**
   - Checks if valid `rawCrawlData` is already persisted from a previous attempt.
   - If present, reuses crawl output (`reusedCrawl: true`).
   - If absent, transitions status to `CRAWLING`, runs `crawlWebsite()`, and persists `rawCrawlData`.
3. **Status Transition:** Updates status to `ANALYZING`.
4. **AI Analysis:** Invokes `analyzeSeoAudit()` with bounded crawl evidence.
5. **Persistence:** Saves `aiAnalysisData: aiResult`, `score: aiResult.overall_score`, sets status to `COMPLETED`, and timestamps `completedAt`.

## 8. Mock vs. Live Mode Behavior

- **Mock Mode (`USE_MOCKS="true"` or `options.useMocks = true`):**
  - Returns `getDeterministicMockAiResult(data)` with `audit_version: "2026.1-mock"`.
  - Zero API calls made to Anthropic.
  - Returns fully schema-compliant, scored results dynamically reflecting the provided crawl findings.
- **Live Mode (`USE_MOCKS="false"`):**
  - Requires valid `ANTHROPIC_API_KEY`.
  - If key is missing or is placeholder (`mock-*`), explicitly throws `ClaudeNotConfiguredError`.
  - Refuses to fake live results or silently substitute mock data when live API calls fail.

## 9. Error Handling & Retry Policies

- **Transient Errors (`ClaudeRateLimitError` [429], `ClaudeTimeoutError`, 5xx):**
  - Persists sanitized error message to `errorMessage` in PostgreSQL.
  - Leaves audit record available for retry.
  - Throws standard `Error` allowing BullMQ exponential backoff retries.
  - On retry, existing `rawCrawlData` is reused without recrawling.
- **Permanent Errors (`ClaudeNotConfiguredError`, schema rejection, SSRF block):**
  - Persists `status: "FAILED"` to PostgreSQL.
  - Throws `UnrecoverableError` so BullMQ immediately halts further retries.
- **Credential Masking:**
  - Strips API keys (`sk-ant-***`), database credentials (`:***@`), and sensitive query params from all stored error strings.
